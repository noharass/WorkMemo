## 3. 新增故障测试如何工作

新测试只使用系统临时目录中本轮创建的 workmemo-phase7-* 文件夹。递归清理前核对真实绝对路径的父目录和固定名称前缀，不使用用户工作目录或真实数据目录。

进程测试由 Rust 测试程序启动同一测试程序的指定用例。父进程创建唯一目录和 worker-marker；子分支检查目录、前缀及标记后才运行。子进程完成一条任务，启动另一条，保存 2500 ms 检查点和独立外观，再留下 800 ms 未保存尾段，使用退出码 27 直接退出。父进程将 27 作为预期结果，确认 WAL 存在后重开原数据库。

检查恢复任务 id 不变、2500 ms 不变、暂停与 recovery_pending、已完成历史和外观；继续 500 ms 后结束，总有效时长 3000 ms，不补计停机或未保存尾段。最终运行 PRAGMA integrity_check。这是真实子进程退出与文件恢复测试，不是断电或存储硬件耐久性证明。

长序列使用固定种子的 1536 次混合事件与独立暂停/时长模型逐次比对，可重复复现。容量测试的 1 万条记录也只写入隔离测试库，不导入产品。

本轮 1 万条首/末页查询合计测得 118 ms（debug 测试程序、包含两次完整汇总、与其他测试并行）；这是一次本机观测，没有设容易波动的时间断言，不作为通用延迟承诺。

人工验收预期：

1. 选类别、正数量和实际备注开始任务，暂停后有效时长保持，继续后在原时长上累计；暂停时换肤和窗口操作不改变任务。
2. 暂停后只点击标题栏保存关闭，重开后同 id、同累计毫秒、暂停且提示恢复；期间不要结束或另建任务，以免破坏比较基准。
3. 继续并结束该任务，最近记录、历史和统计出现同一条完成记录；暂停或关闭时间不应计入。
4. 打开真实历史的删除确认，按 Esc 只关闭确认框，历史面板仍打开，记录保持；无需为本项删除任何真实记录。
5. 四种皮肤和透明度下文字可读、面板能透出桌面；保存后重开保持。移动、缩放、最小化恢复可用。
6. 失败与进程退出只使用隔离自动测试，不对真实数据库制造故障，不强制结束用户正在记录的应用。
